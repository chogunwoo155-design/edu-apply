# AI 코딩 도구 사용 내역

## 쓴 도구

| 도구 | 쓴 곳 |
|---|---|
| Claude Code (Claude Opus) | 코드·테스트 작성, 기기별 화면 점검 스크립트, 문서 초안 |
| Claude Code 하위 에이전트 2개 | 1차 구현만 보고 흠을 찾는 독립 리뷰 (코드·운영 1, 화면·사용성 1) |

커밋마다 `Co-Authored-By: Claude`를 남겼습니다.

## 왜 이렇게 나눴나

이 과제를 받은 지원자 대부분이 AI로 만들 것이라고 봤습니다. 그러면 "요구사항대로 동작한다"는 차별점이 되지 않습니다.
그래서 **AI가 빨리 만들어 주는 1차 결과물**과, **사람이 기준을 정하고 고쳐 나가는 과정**을 나눠서 보이게 했습니다.

제가 정한 기준은 네 가지입니다.

1. 먼저 요구사항대로 만든다 (1차 커밋)
2. 만든 결과물을 다른 눈으로 다시 보고 개선한다. 1차를 만든 세션과 다른 AI 세션에 리뷰를 맡기고, 그 리포트를 근거로 2차를 고친다
3. UI는 정말 깔끔하게, 토스처럼 한 화면에 한 가지 일만 하게. 사람 사진은 쓰지 않는다. 반응형은 폰·폴더블·태블릿·PC를 모두 본다
4. 공고의 주요 업무 중 **배치·자동화 작업 개발**과 **기존 서비스 개선·리팩토링**을 미리 보여 주는 구성으로 만든다

## 진행 순서

| 2차 | 리뷰의 막음·큼 항목부터 고침. 테스트 33개, 화면 점검 71개 통과 | 커밋 `2차-1~3`, `docs/IMPROVEMENT_LOG.md` |

## AI를 쓸 때 지킨 것

- **확인하지 않은 것은 됐다고 하지 않는다.** 화면은 실제 브라우저(Chromium, WebKit)로 13개 기기 크기를 자동 점검하고, 캡처를 직접 열어 봤습니다. 숫자가 다 통과한 뒤에도 캡처에서 찾은 문제가 있었습니다(요일이 "화요일요일"로 나옴, 폰에서 관리 메뉴가 글자 단위로 줄바꿈).
- **고치기 전에 재현부터.** 리뷰에서 나온 결함은 먼저 실패하는 테스트를 만들고 고쳤습니다.
- **AI가 놓친 것도 남긴다.** 1차 점검 도구가 "통과"라고 했던 화면에서 리뷰가 막음 등급 두 개를 찾았습니다. 리포트를 지우지 않고 두었고, 왜 놓쳤는지와 무엇을 더 검사하게 했는지 적었습니다.
- **확인 못 한 것은 못 했다고 적는다.** 실제 Google 시트 연결, 실제 AWS 배포, 실제 iPhone Safari는 확인하지 못했고 문서에 그렇게 적었습니다.
