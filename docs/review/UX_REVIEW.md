## 고칠 것 (값이 큰 차례)

1. **[막음] 완료 화면이 처음부터 폼 아래에 보인다.** `.done { display:grid }`(app.css:190)가 `hidden` 속성을 이긴다. 모든 기기에서 폼 밑에 "✔ 신청이 접수됐어요 / 에 담당자가 연락드릴게요 / (으)로 보냈어요"가 빈칸째로 보이고, 폰에서는 체크 아이콘이 하단 버튼 뒤로 삐져나온다(`var/shots-v1/phone__apply.png`, `fold-cover__apply.png`, `desktop-qhd__apply.png`). → `[hidden]{display:none !important}`를 전역에 넣는다.
2. **[막음] 노트북·태블릿 가로·FHD·QHD 신청서의 하단 버튼이 화면 전체 폭(1366~2560px)으로 늘어난다.** 1024px 이상에서 숨기는 규칙이 `.landing ~ .bottom-cta`(app.css:213)뿐이라 신청서는 해당이 없다. 폼은 y≈570에서 끝나는데 버튼은 y≈1090 바닥에 붙는다. 폴드 펼침(690px)에서도 버튼(650px)이 폼 칸(600px)보다 넓어 좌우 끝이 안 맞는다. → `.bottom-cta` 안쪽을 `max-width: 640px; margin: 0 auto`로 폼 칸과 맞추고, 768px 이상에서는 고정을 풀어 폼 바로 아래에 둔다.
3. **[큼] 오류 문구가 DRF 기본 번역 그대로다.** 빈칸 제출 시 "이 필드는 blank일 수 없습니다." ×3, 날짜는 "Date의 포멧이 잘못되었습니다. 이 형식들 중 한가지를 사용하세요: YYYY-MM-DD."(`shots/phone_empty_submit.png`). → 시리얼라이저 `extra_kwargs`의 `error_messages`로 칸별 문장을 쓴다: "이름을 적어 주세요", "이메일을 적어 주세요", "주소를 찾아 주세요", "연락받을 날짜를 골라 주세요".
4. **[큼] 주소 검색이 없다.** 한국 사용자는 "주소 찾기"를 누르는 데 익숙하다. 지금은 "서울"만 적어도 통과하고, 모델의 `postcode` 칸은 비어 있다. → 카카오(다음) 우편번호 서비스(키 필요 없음)를 붙인다. 주소 칸을 누르면 모바일은 전체 화면 시트, 데스크톱은 레이어로 열고, 고르면 도로명 주소와 우편번호를 채운다(읽기 전용). 그다음 상세 주소 칸에 포커스를 둔다. 스크립트를 못 불러오면 직접 입력으로 대신한다.
5. **[큼] 연락 날짜 고르기가 불편하다.** Chromium에서는 영어 "yyyy-mm-dd"가 보이고, WebKit(iOS)에서는 안내 없는 빈 상자가 보인다(`var/shots-v1/phone__apply.png`). 요일이 나오지 않고 `max`도 없어 2099년도 고를 수 있다. `ui_check.py:66`이 `.date-chips`를 예외로 두는 것을 보면 칩을 만들려다 만 것 같다. → 영업일 기준 7~10일을 가로 스크롤 칩으로 보여 준다("내일 11/28 (금)", "11/30 (월)" …). 마지막 칩 "다른 날짜"를 누르면 기본 달력을 연다. 고른 날짜는 "12월 1일 (화)"처럼 다시 보여 준다.
6. **[큼] 개인정보 수집·이용 동의가 없다.** 이름·이메일·주소를 모으고, 대상에 중1(만 13세)이 들어 있다. 만 14세 미만이면 법정대리인 동의도 필요하다(짐작: 법무 확인 필요). 하단에 개인정보처리방침 링크도 없다. → CTA 위에 "[필수] 개인정보 수집·이용 동의 보기 ›" 한 줄을 두고, 누르면 항목·목적·보관 기간을 바텀시트로 보여 준다. 보호자가 신청하는 경우와 학생이 신청하는 경우를 문구로 정한다(아래 8번).
7. **[큼] 서버 오류도 전부 "네트워크 오류"로 나온다.** HTML 500·403(CSRF)·429에서 `res.json()`이 예외를 던져 같은 문구로 떨어진다(apply.js:52, `shots/phone_network_fail.png`). 운영에서 메일 발송이 실패하면 신청은 이미 저장된 뒤 500이 난다(api.py:35-44). 사용자는 실패로 알고 다시 내서 같은 신청이 두 번 생긴다(짐작: 지금은 콘솔 메일이라 재현 안 됨). → 메일 발송을 `transaction.on_commit` + try/except로 감싸 실패해도 201을 돌려준다. 프런트는 상태 코드별로 문구를 나누고 "다시 시도" 버튼을 둔다. 서버는 같은 교육·같은 이메일이면 409 "이미 신청하셨어요"로 막는다.
8. **[큼] 신청하는 사람이 누구인지 알 수 없다.** 대상은 중·고등학생인데, 폼은 이름 하나만 받는다. 학생 이름인지 보호자 이름인지, 이메일이 누구 것인지 알 수 없다. → 필드는 늘리지 않고 라벨만 정한다: "학생 이름", "연락받을 이메일 (보호자도 괜찮아요)". 짐작: 과제 명세가 필드를 고정했을 수 있다.
9. **[큼] 관리 화면에서 상태를 바꾸면 페이지 전체가 다시 열리고 필터가 풀린다.** `redirect("manage:list")`(views.py:38)가 `?status=`와 스크롤 위치를 버리고, 바꿨다는 안내도 없다. `request.POST["status"]`는 검사 없이 저장되고(views.py:36), 값이 없으면 500이 난다. → 이미 있는 `PATCH /api/applications/<id>/`를 fetch로 불러 그 줄만 바꾼다. 하단에 토스트 "UX리뷰 님 → 확인중 · 되돌리기"를 띄운다. 서버는 `Status.values`로 검사한다.
10. **[큼] 관리 화면에 개수·검색·정렬·상세 보기가 없다.** 탭에 개수가 없고, 이름·이메일 검색, 교육 필터, "오늘 연락할 사람"이 없다. 정렬은 신청일 최신순으로 고정돼 있다. 주소·상세 주소·담당자 메모를 볼 곳도 적을 곳도 없고, 페이지 나누기도 없다. → 탭을 "접수 12 · 확인중 3 · 완료 40"으로 바꾼다. 위에는 "오늘 연락 n명 / 지난 날짜 n명" 요약 칩을 둔다. 검색창과 교육 선택을 두고, 연락일 오름차순을 기본으로 한다. 연락일이 지났는데 아직 접수 상태인 줄은 빨간 표시를 한다. 줄을 누르면 오른쪽 패널(모바일은 바텀시트)에 전체 정보, 메모, `mailto:`, 이메일 복사를 보여 준다. 50건씩 나눈다.
11. **[큼] 관리 화면을 폰에서 못 쓴다.** 390px에서는 신청일·이름·교육만 보이고, 이메일·연락일·상태는 가로 스크롤 밖에 있다(`shots/manage_phone_fold.png`). 상태 선택 높이는 36px이다. → 768px 미만에서는 카드 목록으로 바꾼다(이름·교육 / 연락일 D-day / 상태 칩). 상태는 칩을 눌러 바텀시트에서 고르게 하고, 높이는 44px 이상으로 한다.
12. **[큼] 키보드에서 이동·Enter를 누르면 바로 제출되고, 오류가 늦게 나온다.** 첫 칸(이름)에서 iOS "이동"을 누르면 폼이 제출되고 나머지 빈칸 3개가 한꺼번에 빨갛게 된다. 검사는 제출할 때만 하고, 고쳐 입력해도 빨간 표시가 남는다. 처음 오류가 나면 포커스는 BODY로 가고 첫 오류 칸으로 가지 않는다. 날짜 오류 문구는 하단 버튼 뒤에 가려진다(`shots/phone_empty_submit.png`). → `enterkeyhint="next"`를 달고, Enter를 누르면 다음 빈칸으로 옮긴다(마지막 칸에서만 제출). 검사는 blur 때 하고, 입력하면 그 칸의 오류를 지운다. 제출이 실패하면 첫 오류 칸에 포커스한다. `html{scroll-padding-bottom: calc(var(--cta-h) + 16px); scroll-padding-top: var(--topbar-h)}`를 넣는다.
13. **[큼] 완료 화면이 마무리를 못 한다.** 날짜가 "2026-12-01"처럼 ISO 그대로 나온다. "(으)로"는 어색하다. 무엇을 신청했는지 요약이 없다. URL과 제목은 그대로라서 새로고침하면 빈 신청서가 다시 나오고, 같은 신청을 또 넣을 수 있다. 포커스도 옮기지 않는다. → "12월 1일 (화)에 연락드릴게요"로 바꾸고, 교육명·이메일을 요약 카드로 보여 준다. 주 버튼 "확인"은 하단 고정으로 둔다. `history.replaceState`로 `/apply/done/?id=` 같은 서버 렌더 완료 페이지로 옮기고, 완료 제목(`tabindex=-1`)에 포커스한다. 메일 문구는 "메일로도 보내 드렸어요"로 바꾼다.
14. **[큼] 폰 가로·폴드 펼침·태블릿 세로 소개 화면은 첫 화면이 거의 그림이다.** 정보표(대상·참가비·마감)가 시작하는 위치: 폰 가로 762px(화면 393px), 폴드 펼침 762/829px(`var/shots-v1/fold-open__detail.png`). 폰 가로에서는 상단 바 56px와 하단 버튼 80px가 높이 393px의 35%를 덮고, 신청서 첫 칸도 반쯤 가린다(`shots/landscape_apply.png`). → `@media (max-height:500px)`에서는 상단 바 고정을 풀고 하단 버튼을 폼 끝에 둔다. 소개 화면은 600px 이상이고 가로가 더 길면 2단 히어로로 바꾸고, 그림은 `max-height: 40vh`로 줄인다. 하단 버튼 위에는 "무료 · 12월 11일 마감" 한 줄을 넣는다.
15. **[큼] 다크 모드가 없다.** 다크 설정 폰에서도 흰 화면 그대로다(`shots/dark_apply.png`). 흰색이 곳곳에 하드코딩돼 있다: `theme-color #fff`(base.html:6), 상단 바 rgba 흰색(app.css:59), 하단 버튼 그라데이션 `#fff`(app.css:120), 입력칸 `#fff`(app.css:178). `color-scheme` 선언도 없어서, 안드로이드 크롬 "강제 다크"가 일러스트 색을 뒤집을 수 있다(짐작). → 토큰에 `@media (prefers-color-scheme: dark)` 값을 넣고, `<meta name="color-scheme" content="light dark">`와 다크용 `theme-color`를 둔다. 일러스트 SVG 배경은 투명하게 하거나 다크용을 만든다. 다크를 미룰 거면 적어도 `color-scheme: light`로 고정한다.
